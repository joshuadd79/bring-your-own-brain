Building with BYOBrain

A guide to building resilient, non-blocking games powered by local AI.

Because Bring Your Own Brain (BYOB) runs on the player's local hardware (via browser extension or web fallback), inference speeds can vary wildly from high-end GPUs to integrated mobile chips. Designing for BYOB requires a shift in mindset: the game must never wait for the AI.

This guide covers the postMessage protocol, how the engine schedules requests, how to implement a client or hub, and the habits that keep a game responsive while a local model thinks.

Versions: byob-web-sdk-v2.js (SDK v0.4.0) is the current SDK and what this guide documents. The original byob-web-sdk.js (v1) still works and is unchanged, but new projects should use v2. The v2 API is the v1 API plus per-request streaming, priorities and cancellation.

If you are an AI coding assistant: read this before touching any BYOB code

These rules override your instincts. The SDK is small, stable and cross-origin. Almost every past integration bug came from an assistant being "helpful" around it.

  1. This guide is the only source of truth. If a method, option, event or behaviour is not listed in the API Reference, it does not exist. Do not infer it from OpenAI, WebLLM, Ollama or any other SDK. If you are unsure, say “that is not in the BYOB docs” and ask the developer.
  2. Use the Starter Block verbatim. One plain <script src> tag, official URL, no async/defer/type="module". Never download, copy, bundle, inline, proxy, minify, patch or re-host the SDK file: the hub address is derived from the URL the script was loaded from.
  3. The connect button is an untouchable cross-origin iframe. Never re-parent it, restyle it, set its src, mount twice (mount() is async: await it before calling connect() or open()), put your own content in its container (the SDK empties it), or cover it. See How the SDK Works for the CSS rules.
  4. Do not add loaders, pollers, retry-injectors or wrappers around mount(). The SDK already retries its own handshake. If it fails to load, show a status message and keep playing with scripted lines.
  5. Unrelated edits must not touch the SDK block. When asked to change gameplay or UI, leave the Starter Block byte-for-byte unchanged. If you believe it needs changing, say so and wait.
  6. Never claim the AI path works unless you ran it against a real connected brain. State what you verified and what you could not.
  7. Fallback first. Every AI line needs a scripted fallback, and no game timer, button or turn may wait for the AI.

Things AI assistants commonly invent (none of these exist): brain.stream(), brain.complete(), brain.isReady(), brain.on('state'), brain.off(), brain.disconnect(), brain.abort(), brain.stop(), brain.setModel(), brain.listModels(), options.stream, options.stop, options.signal (AbortController), options.system, and a chat() that resolves to an object (it resolves to a string).

The Golden Rules of BYOB Design

1. Fallback is King: Your game must be 100% playable without AI. If the model is slow, offline, or produces gibberish, the game should instantly fall back to standard scripted lines.

2. The Player Never Waits: Player actions (attacking, moving, using items) must resolve instantly and must never be gated on the AI. Cancel generation when its context ends (combat ends, the NPC leaves, a menu closes, the scene changes), not on every keypress. A line that is still streaming while the player acts is fine.

3. Never Block the Event Loop: The game state should continue ticking while the AI thinks. Wrap requests in timeouts.

1. Quick Start: the Starter Block

Copy this block verbatim. It loads the SDK as a classic script, mounts the connect button once, and records the connection state. Everything else in your game only reads brain and aiReady().

<!-- Load the SDK: plain classic script, official URL, no async/defer/module -->
<script src="https://bringyourownbrain.org/byob-web-sdk-v2.js"></script>

<!-- Container for the connect button: keep it a plain, unstyled block -->
<div id="ai-connector"></div>
<div id="ai-status">Loading AI…</div>

<script>
  // === BYOB SDK START: copy verbatim, do not modify ===
  var brain = null, byobState = 'idle', byobMsg = '', byobHeard = false;
  function aiReady() { return !!brain && byobState === 'ready'; }
  function showStatus() {
    document.getElementById('ai-status').textContent =
      aiReady() ? 'Local AI connected' : (byobMsg || 'Press the green button to connect your local AI');
  }
  if (window.BringYourOwnBrainWeb) {
    brain = new BringYourOwnBrainWeb({
      container: document.getElementById('ai-connector'),
      width: '220px', height: '44px',
      onState: function (state, message) {      // 'idle' | 'ready' | 'error'
        byobHeard = true; byobState = state; byobMsg = (state === 'error') ? (message || 'error') : '';
        showStatus();
      }
    });
    brain.mount();                              // async (returns a Promise). Call ONCE; don't call connect()/open() until it resolves.
  }
  setTimeout(function () {                      // hub never answered: offline, blocked or wrong URL
    if (!byobHeard) { byobMsg = brain ? 'Cannot reach bringyourownbrain.org' : 'AI SDK failed to load'; showStatus(); }
  }, 6000);
  showStatus();
  // === BYOB SDK END ===
</script>

Prefer the BringYourOwnBrainWebV2 global if your page might also load the v1 SDK: v2 always defines it, but only claims the plain BringYourOwnBrainWeb name when v1 is absent. Never load both.

2. How It Works

Verified against SDK v0.4.0 and the extension source. Nothing here is inferred.

Game page --(SDK)--> iframe (the "hub") --> extension service worker --> offscreen engine (model on GPU/CPU)
   ^                    |  web hub (bringyourownbrain.org) OR extension hub (chrome-extension://ID/web/connect.html)
   +---- postMessage ---+  The model never runs inside your page.
  • Choosing a hub. await brain.mount() first probes for the extension (a fetch of chrome-extension://ID/web/ping.txt, 400 ms timeout per ID). Found: the extension hub is used (offline capable, shared models). Not found, or the page’s CSP blocks the probe: the website hub is used. brain.mode ('extension' | 'web') is only final after mount() resolves.
  • mount() is async. brain.iframe does not exist until the probe finishes (up to ~0.4 s). Calling connect() or open() before it resolves starts a second mount: without a container you get two iframes (two buttons); with a container the first iframe is thrown away and rebuilt. Call mount() once; await it if you need the iframe or mode.
  • The SDK owns the container. It empties container (innerHTML = '') and puts the iframe in it. With no container the iframe floats bottom-right. If the browser is offline and the extension is absent, no iframe is created: the container shows a short warning and onState('error', 'Needs extension for offline use.') fires.
  • Handshake. The SDK sends BYOB_HELLO every 100 ms (about 5 s) until the hub sends any message. After that it stops. There is no further retry: do not re-mount.
  • Origins are checked both ways. The SDK ignores messages whose source is not its iframe or whose origin is not the hub’s. The hub accepts a parent on http(s) or on a file:// page (origin 'null', replied to with target '*').
  • Functions cannot cross postMessage. The SDK removes onChunk from options before sending. Do not put other functions or non-cloneable values in options.
  • Chunks are deltas. onChunk(text) gets only new text. A per-request onChunk beats the shared brain.onChunk; with more than one request in flight, always pass it per request.
  • onState runs synchronously inside the SDK’s message handler. Keep it short and never let it throw.
  • The connect UI expands the iframe full screen (position: fixed; inset: 0; z-index: 2147483647) and collapses it later. No ancestor of the container may use transform, filter, perspective, contain or will-change (the fixed overlay would be clipped), and none may be a low-z-index stacking context beneath your overlays. Start your own overlays below the connector.
  • Loading. The hub URL is derived from document.currentScript.src, so load the SDK as a classic script from bringyourownbrain.org. Loading it twice is harmless (the second copy exits).

3. The Protocol (postMessage)

Both hubs speak the same protocol, so the SDK and your game cannot tell them apart. All messages are plain objects with a type string.

Parent page → hub

typefieldsmeaning
BYOB_HELLO—“Are you there?” Sent every 100 ms until the hub replies. The hub records the sender’s origin and must answer; repeats must be harmless.
BYOB_OPEN—Start the connect flow now (brain.open()). Ignored if already expanded.
BYOB_CHATid, payload: { messages, ...options }Start a generation. id is unique per request. payload is the options object minus onChunk.
BYOB_CANCELidStop that request (running or queued). Unknown ids are ignored.

Hub → parent page

typefieldsmeaning
BYOB_STATEstate, message?'idle' not connected or user backed out · 'ready' engine running and this site approved · 'error' (see message) · 'denied' user declined the notice or the “Allow this site?” prompt. 'ready' can revert to 'idle' (for example “Forget this site”).
BYOB_UIaction'expand' (iframe should go full screen) or 'collapse' (back to the compact button). The SDK does the resizing.
BYOB_STREAM_EVENTstreamId, eventType, textCHUNK (text = new text only) · DONE · ERROR (text = message) · CANCELLED (text = reason: 'cancelled', 'preempted' or 'dropped').

Rules (what a conforming hub and client must do)

  • Every request ends with exactly one terminal event (DONE, ERROR or CANCELLED). Nothing is ever left hanging. Clients may rely on this, but should still use a timeout.
  • streamId equals the request id. Ignore events for ids you did not issue.
  • The client resolves with the concatenation of all CHUNK texts; the text of DONE is not used.
  • A request sent while the hub is not ready gets ERROR (“Not connected…”). The SDK also rejects locally, without sending anything, unless state === 'ready'.
  • Check event.source and event.origin on every incoming message, in both directions. Never use '*' as target except for a file:// parent (origin 'null').

Typical sequence

SDK:  mount() -> probe extension -> create iframe -> BYOB_HELLO (every 100 ms)
Hub:  BYOB_UI collapse, BYOB_STATE idle|ready        (approved site: engine starts itself, then 'ready')
User: clicks button -> Hub: BYOB_UI expand -> 18+ notice -> "Allow this site?" -> model download -> BYOB_STATE ready -> BYOB_UI collapse
Game: chat() -> BYOB_CHAT {id}      Hub: CHUNK, CHUNK, ... DONE   (or ERROR / CANCELLED)
Game: p.cancel() -> BYOB_CANCEL {id}   Hub: CANCELLED 'cancelled'

4. Engine Behaviour (what happens behind the hub)

Verified in the extension source. These are hard facts you can design around.

TopicBehaviour
ConcurrencyOne model on one device: one generation at a time. Everything else waits in a queue.
Priorities'low'=1, 'normal'=2 (default), 'high'=3 (a number 1–3 also works). A higher-priority request preempts a running lower one (it ends with CANCELLED 'preempted'). Within the queue, higher priority goes first, then oldest first.
Queue capsPer priority: low 2, normal 4, high 12. Beyond the cap the oldest waiting request of that priority is dropped (CANCELLED 'dropped'). Spamming requests silently discards your older ones.
LimitsOnly the last 64 messages are used; each message is cut at 32,000 characters; max_tokens is capped at 1,024 and defaults to 120 if omitted; temperature defaults to 0.7.
Safety textA short generic safety paragraph is appended to your system message (the player can turn this off). Budget a few dozen tokens for it; it does not forbid in-character insults.
Rolesdeveloper maps to system, model to assistant, anything unknown to user.
Slow startsIf the engine slept (idle about 10 min) the next request wakes it first. If the engine does not accept a request within 8 s the hub sends ERROR 'The local AI engine did not respond. Try again.' Use generous timeouts and always have a fallback.
Tab closedClosing the game tab cancels its running request.
ApprovalPer site (origin; file:// pages are stored as 'file://'). An approved site starts the engine silently; a new site must go through the notice and consent first.
PrivacyConversations are not stored; only local counters (tokens, bytes not re-downloaded) are kept for the player’s receipt.

5. Implementing the Protocol Yourself

Almost everyone should use the SDK. If you must talk to a hub directly (a non-browser host, a test harness, or your own hub), the minimal client below is the whole protocol. For the browser, loading the real SDK is strictly better because it also finds the extension.

// Minimal client. HUB must be the exact hub URL; ORIGIN its origin.
const HUB = 'https://bringyourownbrain.org/connect-v2.html', ORIGIN = new URL(HUB).origin;
const frame = document.createElement('iframe'); frame.src = HUB; document.getElementById('slot').appendChild(frame);
let state = 'idle', heard = false;

addEventListener('message', (e) => {
  if (e.source !== frame.contentWindow || e.origin !== ORIGIN) return;   // both checks, always
  const d = e.data || {}; heard = true;
  if (d.type === 'BYOB_STATE') state = d.state;                          // 'idle' | 'ready' | 'error' | 'denied'
  if (d.type === 'BYOB_UI') { /* expand: make the iframe fixed full screen; collapse: restore the compact size */ }
});

let tries = 0;
const hello = setInterval(() => {                                         // handshake: repeat until the hub answers
  if (heard || tries++ > 50) return clearInterval(hello);
  frame.contentWindow && frame.contentWindow.postMessage({ type: 'BYOB_HELLO' }, ORIGIN);
}, 100);

function chat(messages, options, onChunk) {
  const id = 'req_' + Date.now() + '_' + Math.random().toString(36).slice(2, 7);
  const p = new Promise((resolve, reject) => {
    if (state !== 'ready') return reject(new Error('not connected yet'));
    let text = '';
    const on = (e) => {
      const d = e.data || {};
      if (e.source !== frame.contentWindow || e.origin !== ORIGIN || d.type !== 'BYOB_STREAM_EVENT' || d.streamId !== id) return;
      if (d.eventType === 'CHUNK') { text += d.text; onChunk && onChunk(d.text); return; }
      removeEventListener('message', on);                                 // every other event is terminal
      if (d.eventType === 'DONE') resolve(text);
      else if (d.eventType === 'ERROR') reject(new Error(d.text || 'Inference error'));
      else { const err = new Error('cancelled'); err.cancelled = true; err.reason = d.text; err.partial = text; reject(err); }
    };
    addEventListener('message', on);
    frame.contentWindow.postMessage({ type: 'BYOB_CHAT', id, payload: { messages, ...options } }, ORIGIN);
  });
  p.cancel = () => frame.contentWindow.postMessage({ type: 'BYOB_CANCEL', id }, ORIGIN);
  return p;
}

Implementing a hub instead? Follow the rules in section 3 and: answer every BYOB_HELLO with BYOB_UI and BYOB_STATE; validate the parent’s origin and remember it; end every request with exactly one terminal event; map engine failures to ERROR; cancel running work when asked, when the parent goes away, or when a more important request arrives.

6. Healthy Non-Blocking Handling

The model shares the player’s hardware with your game, so a healthy integration treats AI text as a garnish that may arrive late, early, or never. These are the habits that make that work.

  1. Two worlds, one direction. Game logic never reads AI state to decide what happens next. The AI layer reads game state and decorates it. Attacks resolve, doors open and timers tick whether or not any text exists.
  2. Gate on aiReady(), not on hope. Treat 'idle', 'error' and 'denied' as “scripted mode” and keep the status text honest. Re-check before every request: 'ready' can revert.
  3. One request per speaker, with a gap. The engine runs one generation at a time and drops the oldest queued request beyond the cap, so a speaker should never have two in flight. Start the next after the last finishes plus a gap (3 s, or as long as the last took).
  4. Priority matches visibility. What the player is looking at is normal or high. Background pre-cooking is low, expecting to be dropped.
  5. Cancel on context end, not on every action. When combat ends, an NPC leaves or a menu closes, cancel. While the context lives, let the line finish even if the player keeps acting.
  6. Every path has a fallback line: timeout, ERROR, CANCELLED, invalid text, offline, not approved.
  7. Start requests off the critical path: after rendering, via setTimeout(fn, 1).
  8. Stream through a queue (section 10) so bursts look smooth, and show “…” while waiting for the first token.

A reference implementation of habits 2–6 and 8:

// One "speaker" (an enemy, an NPC). Never has two requests in flight; always ends with a line.
function createSpeaker(el, getMessages, fallbackLines, opts) {
  let task = null, alive = true, timer = null, token = 0;
  opts = Object.assign({ priority: 'normal', max_tokens: 48, temperature: 0.9, timeoutMs: 20000, gapMs: 3000 }, opts);

  function show(text) { if (alive) el.textContent = text; }
  function scripted() { return fallbackLines[Math.floor(Math.random() * fallbackLines.length)]; }

  function speakOnce(done) {
    const my = ++token;
    if (!aiReady()) { show(scripted()); return done(); }          // scripted mode
    show('…');
    let queue = '', first = true, final = null, finished = false;
    const drain = setInterval(() => {
      if (my !== token || !alive) return clearInterval(drain);    // stale: a newer line or the context ended
      if (queue) { const n = Math.max(1, Math.ceil(queue.length / 10)); el.textContent += queue.slice(0, n); queue = queue.slice(n); }
      else if (finished) { clearInterval(drain); show(final || scripted()); done(); }
    }, 20);
    task = askBrainSafe(getMessages(), Object.assign({}, opts, {
      onChunk: (t) => { if (my !== token) return; if (first) { first = false; el.textContent = ''; } queue += t; }
    }), opts.timeoutMs);
    task.promise
      .then((raw) => { const s = cleanAiText(raw); final = isValidLine(s) ? s : null; })
      .catch((err) => { const s = cleanAiText(err && err.partial); final = isValidLine(s) ? s : null; })
      .finally(() => { task = null; finished = true; });
  }

  function loop() {
    if (!alive) return;
    const t0 = Date.now();
    speakOnce(() => { timer = setTimeout(loop, Math.max(opts.gapMs, Date.now() - t0)); });
  }
  return {
    start() { timer = setTimeout(loop, 1); },                      // off the critical path
    stop()  { alive = false; token++; clearTimeout(timer); if (task) task.cancel(); }   // call when the context ends
  };
}

7. The Safe Request Wrapper

Do not just await brain.chat(). Instead, wrap requests with a Promise.race timeout so your game doesn't hang if the user's GPU is overloaded.

/**
 * Safe, cancellable wrapper for AI requests.
 * @param {Array} msgs - Messages array
 * @param {Object} opts - BYOB options (priority, max_tokens, etc)
 * @param {Number} timeoutMs - Max time to wait before bailing
 */
function askBrainSafe(msgs, opts, timeoutMs = 8000) {
    const result = { cancel: () => {}, promise: null };
    
    try {
        // 1. Initiate request
        const p = brain.chat(msgs, opts);
        
        // 2. Expose the native cancel method
        result.cancel = () => { try { p.cancel(); } catch(e){} };
        
        // 3. Setup Race Condition for Timeout
        let timer;
        const to = new Promise((_, reject) => {
            timer = setTimeout(() => {
                result.cancel(); // kill generation
                reject(new Error('timeout'));
            }, timeoutMs);
        });

        // 4. Return the raced promise
        result.promise = Promise.race([p, to]).finally(() => clearTimeout(timer));
    } catch(e) {
        result.promise = Promise.reject(e);
    }
    
    return result;
}

8. Priorities & Compute Management

The BYOB engine queues requests by priority. A higher-priority request preempts a lower one that is running, and low-priority requests are dropped first. The affected promise rejects with err.cancelled and err.reason of 'preempted' or 'dropped'. 'normal' is the default. Only one generation runs at a time, and each priority has a queue cap (low 2, normal 4, high 12): beyond it the oldest waiting request is dropped.

  • high Direct Player Interaction: The player clicked a character and is waiting for a response. Maximize tokens/speed.
  • normal Reactions the player can see: an enemy taunting during combat, an NPC reacting to a bump. Anything on screen right now belongs here or in high, never in low.
  • low Invisible background work: pre-cooking idle lines nobody is looking at. Will be dropped automatically if a high priority task comes in.
// The player is waiting for this:
const reply = brain.chat(messages, { 
    priority: 'high', 
    max_tokens: 40,
    temperature: 0.8
});

// A background NPC is just thinking:
const ambient = brain.chat(messages, { 
    priority: 'low', 
    max_tokens: 20 
});

9. Cancellation (Stop the GPU)

If an NPC is talking or generating text, and the player walks away or attacks them, you must cancel the promise. cancel() asks the hub to stop; the promise then rejects with err.cancelled once the hub confirms. A request still waiting in the queue is dropped at once, and a running generation stops promptly, freeing the player’s hardware.

let currentAiTask = null;

function chatWithNPC(npc, text) {
    // If they were already generating something else, kill it!
    if (currentAiTask) {
        currentAiTask.cancel(); 
    }

    currentAiTask = askBrainSafe([...], { priority: 'high' }, 5000);

    currentAiTask.promise
        .then(reply => npc.say(reply))
        .catch(err => {
            // Handle timeout or manual cancellation gracefully
            if (err.cancelled) return; 
            npc.say("I lost my train of thought..."); // Fallback!
        })
        .finally(() => currentAiTask = null);
}

// When the player triggers combat:
function startCombat() {
    if (currentAiTask) currentAiTask.cancel();
}

10. Streaming UI: the Typewriter Queue

Chunks can arrive in bursts, especially on slow hardware. Never write them straight to the screen. Push each chunk into a queue and drain it on a short timer: a few characters per tick, faster when the queue grows. The text then flows token by token even when delivery is bursty. This is the pattern used by the official chat demo and by the Soul Rogue game.

// Streams one line into `el`. Returns the task so the caller can cancel it when the context ends.
// onDone(text | null): final cleaned text, or null if it was invalid (caller shows a scripted line).
function streamInto(el, msgs, opts, onDone) {
  let queue = '', done = false, final = null, started = false;
  el.textContent = '…';                                   // "thinking" until the first token arrives

  const timer = setInterval(function () {
    if (queue) {
      const n = Math.max(1, Math.ceil(queue.length / 10));   // drains faster when it falls behind
      el.textContent += queue.slice(0, n);
      queue = queue.slice(n);
      // Optional: validate the text so far and bail out early
      // if (!isValidLine(el.textContent)) { task.cancel(); queue = ''; }
    } else if (done) {
      clearInterval(timer);
      if (final) el.textContent = final;                  // replace with the cleaned version
      if (onDone) onDone(final);
    }
  }, 20);

  const task = askBrainSafe(msgs, Object.assign({}, opts, {
    onChunk: function (t) {                               // per request, never the shared brain.onChunk
      if (!started) { started = true; el.textContent = ''; }
      queue += t;                                         // chunks are deltas: append
    }
  }), 20000);

  task.promise
    .then(function (raw) { const s = cleanAiText(raw); final = isValidLine(s) ? s : null; })
    .catch(function (err) { const s = cleanAiText(err && err.partial); final = isValidLine(s) ? s : null; })
    .finally(function () { done = true; });
  return task;
}

// Always use textContent for model output, never innerHTML.
  • Start the request with setTimeout(fn, 1) after the screen has updated, so request setup never delays a game frame or timer.
  • Only one chatter request in flight per speaker. Start the next one after the last finishes, plus a gap (at least 3 s, or as long as the last one took).
  • Guard against stale updates: if the scene changed while text was streaming, stop the timer and ignore late chunks.

11. Pre-cooking & Caching (The Ambient Secret)

Don't generate ambient idle lines on the fly. When the game engine detects the player is idle, use low priority to "pre-cook" lines and store them in an array. When an NPC needs to speak idly, pop a line from the array instantly.

// Run this inside your game tick/loop:
function ambientTick() {
    // Only generate if we aren't busy and the player hasn't done anything recently
    if (isAiBusy || playerIsActive) return;

    const idleNPCs = getNPCsWithEmptyCache();
    if (idleNPCs.length > 0) {
        const target = idleNPCs[0];
        
        // Generate a line in the background
        const task = askBrainSafe(
            [{role: 'system', content: 'Generate a short idle thought.'}], 
            { priority: 'low' }, 
            12000 // give it plenty of time
        );

        task.promise.then(line => {
            if (validateLine(line)) {
                target.dialogueCache.push(line); // Store for later!
            }
        }).catch(() => { /* quietly fail */ });
    }
}

// When the NPC actually needs to speak on screen:
function npcIdleSpeak(npc) {
    if (npc.dialogueCache.length > 0) {
        npc.say(npc.dialogueCache.shift()); // Instant delivery!
    } else {
        npc.say(npc.defaultScriptedLines[0]); // Scripted fallback
    }
}

12. Small Models & CPU

Treat 0.5B–3B models as fast, forgetful improv actors, and expect the player’s phone or laptop CPU to be the slowest target you will ever meet.

  • Keep the prompt tiny. The model must read the entire prompt before the first token, so a long few-shot prompt means seconds of silence on CPU. Aim for about 100 tokens: a 1–3 line system message, one short user line, and at most one short example line.
  • Plain-language roleplay beats key:value templates. “You are Cave Bat, a monster in a dark dungeon. Say ONE short line (max 15 words) to the hero.” works. “Persona: X. Style: Y. Mood: Z.” makes tiny models explain the format instead of speaking.
  • Tell it what it is not. Tiny chat models default to assistant mode (“Hello, how can I help you today?”). Add “You are not an assistant. Never greet or offer help.” and reject replies that still sound like one.
  • Do not ask a model to be unintelligible. It will answer in English. Generate nonsense speech (slimes, animals) locally and use the same typewriter to display it.
  • max_tokens about twice the expected word count (40–60 for one-liners); temperature 0.7–0.9 for chatter.
  • Send only the last 6–10 messages of history.
  • Show a “thinking” indicator (…) and keep the game running. Test on the slowest hardware you support; CPU and GPU can differ by 10×.

13. Data Validation

Local AI models hallucinate. They might spit out Markdown, empty brackets, or system prompts. Never pipe AI text directly to your UI without cleaning it first. If validation fails, throw it away and use a scripted line.

function cleanAiText(raw) {
    // Remove HTML tags, markdown artifacts, and trim
    let s = String(raw || '').replace(/<[^>]*>/g, '').trim();
    
    // Remove common AI prefix bugs (e.g., "Bot Name: ")
    s = s.replace(/^(NPC|Bot|Assistant)\s*:\s*/i, '');
    
    return s;
}

function isValidLine(s) {
    if (!s || s.length < 2 || s.length > 200) return false;
    
    // Catch common model breakages
    if (/\[error|<start_|<\|im_|function_call|as an ai language model|how can i (help|assist)|^\s*(hello|hi|hey)\b/i.test(s)) {
        return false; 
    }
    
    return true;
}

// Usage (inside an async function, or in a .then chain):
async function lineFromBrain(task) {
    const rawText = await task.promise;
    const cleaned = cleanAiText(rawText);
    if (!isValidLine(cleaned)) {
        throw new Error('Invalid AI generation'); // triggers your fallback catch()
    }
    return cleaned;
}

15. Testing Without a GPU

Point the SDK at a mock hub with the hubUrl option (this also disables the extension probe). The mock speaks the real protocol, so it exercises your state handling, streaming, cancellation and fallbacks without a model.

<!-- mock-hub.html (same origin as your test page) -->
<script>
const jobs = {};
addEventListener('message', (e) => {
  const d = e.data || {}, send = (m) => parent.postMessage(m, e.origin);
  if (d.type === 'BYOB_HELLO') { send({ type: 'BYOB_UI', action: 'collapse' }); send({ type: 'BYOB_STATE', state: 'ready' }); }
  if (d.type === 'BYOB_CHAT') {
    const words = 'Skreee! Fresh blood enters my cave, little hero!'.split(/(?<= )/); let i = 0;
    jobs[d.id] = setInterval(() => {
      if (i < words.length) send({ type: 'BYOB_STREAM_EVENT', streamId: d.id, eventType: 'CHUNK', text: words[i++] });
      else { clearInterval(jobs[d.id]); send({ type: 'BYOB_STREAM_EVENT', streamId: d.id, eventType: 'DONE' }); }
    }, 150);                                       // slow it down to feel CPU-speed streaming
  }
  if (d.type === 'BYOB_CANCEL') { clearInterval(jobs[d.id]); send({ type: 'BYOB_STREAM_EVENT', streamId: d.id, eventType: 'CANCELLED', text: 'cancelled' }); }
});
</script>

// In your test build:  new BringYourOwnBrainWeb({ container, hubUrl: '/mock-hub.html', onState })

Then check each of these on purpose:

  • Hub never answers (point hubUrl at a blank page): after 6 s the status says it cannot reach the hub and the game still plays.
  • States 'error' and 'denied', and 'ready' reverting to 'idle' mid-session: scripted lines take over and nothing hangs.
  • Cancel mid-stream and change scene mid-stream: no late text appears in the new scene.
  • Two speakers at once: lines do not mix (per-request onChunk).
  • Slow hub (raise the mock’s interval to 1 s): buttons and timers stay responsive. In Chrome DevTools, Performance → 6× CPU slowdown shows the frame cost of your own streaming code.
  • Offline with no extension: the container shows the SDK’s warning and the game plays scripted.

16. API Reference (complete)

This is everything the SDK exposes. Anything not listed here does not exist.

new BringYourOwnBrainWeb(options)

  • container: DOM element for the iframe. Omit to float bottom-right.
  • width / height: CSS strings for the button (defaults '240px' / '52px'; the demos use '220px' / '44px').
  • onState(state, message): state is 'idle', 'ready', 'error' or 'denied' (the player declined). Called synchronously from the SDK’s message handler.
  • onChunk(text): shared fallback stream handler (prefer per-request onChunk).
  • hubUrl, useExtension, extensionId: advanced hub selection. A custom hubUrl always wins over the extension. Leave unset normally.

Instance members

  • await brain.mount(): probes for the extension, empties the container and attaches the iframe. Returns a Promise (no value). Call once.
  • brain.open(): opens the connect flow now (starts a mount if none exists, so mount first). Use after your own Connect button was clicked.
  • brain.connect(): Promise that resolves {success:true} when the state becomes 'ready'.
  • brain.destroy(): removes the iframe and rejects pending requests with a plain Error (‘bringYourOwnBrain was disconnected.’, no cancelled flag). For teardown only.
  • brain.state, brain.mode ('web' | 'extension'), brain.viaExtension, brain.version, brain.iframe, brain.onChunk, brain.onState.
  • brain.ask, brain.generate, brain.prompt are aliases of brain.chat.

brain.chat(messages, options) → Promise<string>

messages is an array of {role, content} (a plain string is treated as one user message). Rejects immediately if the brain is not 'ready'.

  • options.priority: 'high' | 'normal' (default) | 'low'.
  • options.onChunk(text): streamed delta text for this request.
  • options.max_tokens: default 120, capped at 1024. options.temperature: default 0.7. Other plain (cloneable) values are passed through.

Returns a Promise resolving to the full reply as a string, with .id and .cancel() attached. On cancellation it rejects with an Error where err.cancelled === true, err.reason is 'cancelled' | 'preempted' | 'dropped', and err.partial is the text received so far. Other failures reject with an ordinary Error (err.message). Messages you can meet: ‘bringYourOwnBrain is not connected yet.’ (SDK, not ready), ‘Not connected. Finish the bringYourOwnBrain connect steps first.’ (hub), ‘The local AI engine did not respond. Try again.’ (no accept within 8 s), ‘The local AI engine stopped unexpectedly.’, ‘No model is selected…’, ‘Model is not loaded.’. Treat all of them as “use the scripted line”.
